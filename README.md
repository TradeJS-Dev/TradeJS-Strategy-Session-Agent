# SessionAgent

Intraday-стратегия TradeJS для бессрочных USDT-контрактов Bybit. Портфельный
модуль выбирает до одной сделки на сессию и закрывает её по стопу или к концу
сессии. В репозитории также сохранён первоначальный однотикерный прототип
для BTCUSDT.

## Правила

Для отбора нужны 96 последовательных закрытых свечей M15 и оборот от 10 млн
USDT за последние сутки. Модели и исходный список контрактов для проверенного
исторического прогона зафиксированы в каталоге `calibration/`.

| Сессия   | Часы по местному времени | Вход                                                                                                                             |
| -------- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| Нью-Йорк | 09:30–16:00              | Выбор из топ-12 по обороту. Первое предложение проверяет замороженный AI-gate, обученный на всех доступных ликвидных контрактах. |
| Токио    | 09:00–15:30              | Выбор из топ-24 по обороту. Исходный шорт означает пропуск сессии.                                                               |

Обе сессии проверяют первые три момента входа с шагом M15. Если Нью-Йорк
одобрил предложение при открытии, он ждёт закрытия первой свечи. В 09:45
тикер должен оставаться в топ-12, а фильтр должен снова одобрить исходную
сторону. Если исходное предложение появилось только в 09:45 или 10:00,
дополнительного ожидания нет.

До накопления 20 закрытых бумажных лонгов Токио использует 12,5% от полного
риска. Затем риск равен 25% при положительном суммарном результате последних
20 сигналов и 12,5% в остальных случаях. Бумажный результат обновляется и при
пропуске. Три фактически убыточные сделки подряд означают пропуск следующего
лонга Токио и сброс счётчика. Нью-Йорк использует полную единицу риска.

## Запуск исторической проверки

Нужны Node.js 24, Yarn 4 и локальный архив свечей и ставок фандинга Bybit.
Из этого репозитория установите зависимости и проверьте пакет.

```sh
yarn install --immutable
yarn checks
```

Из каталога вашего TradeJS Project выгрузите свечи из локального Timescale
и запустите проверку. В примере исходники стратегии находятся рядом с
проектом. Скрипт выгрузки читает базу `inv-timescale`.

```sh
strategy=../tradejs-strategy-session-agent
market=data/session-agent-replay

python3 "$strategy/research/export-bars.py" "$market"
node "$strategy/research/portfolio-backtest.mjs" \
  "$market" data/market-history/bybit/funding "$market/result.json"
```

В архиве фандинга для каждого исполненного контракта нужен файл
`<SYMBOL>.json.gz` с полем `rates`. Каждый элемент содержит время в
миллисекундах и ставку. Нужны ставки, покрывающие вход и выход.

Исторический прогон проверяет интервал с 18 ноября 2024 по 17 ноября 2026.
Год перед этим использован для первой калибровки. Команда сверяет число
сделок, итоговый PnL, глубину и длительность просадки, а также хеш кривой после каждой сделки с
[`expected-portfolio.json`](research/expected-portfolio.json).
Результат портфеля после расходов составляет **+871,26 USDT**, максимальная
просадка **84,96 USDT**, самая долгая просадка **125,96 дня**. Если удалить
денежный результат лучшей сделки Токио, PnL составляет **+855,51 USDT**.
Правило выбрано на уже исследованной истории. Для меньшего риска модель
умножает исходный PnL на долю риска. Округление лота в торговом адаптере
может изменить исполнение.

## Использование в TradeJS

`createPortfolioSessionAgent(calibration, lotRules)` создаёт один общий
экземпляр на портфель. Передавайте ему синхронизированные срезы закрытых свечей
через `onFrame`, начиная с открытия сессии. `marketRowFromCandles` строит
признаки одного контракта. Возвращённый план с нулевым риском учитывается
только на бумаге. Для каждого плана Токио передайте в `settle` бумажный и
фактический результат после закрытия. `snapshot` возвращает состояние для
следующего запуска между завершёнными сессиями.

Ведущий процесс должен собирать общий срез рынка, передавать планы в
соответствующий тикеру `StrategyAPI` через `enterPortfolioOrder` и
`closePortfolioOrder` и сохранять незавершённые планы и состояние портфеля.
Для регистрации портфельной версии используйте
`createSessionAgentPortfolioPlugin(host)` с этим ведущим процессом.
Стандартная регистрация `strategyEntries` по-прежнему запускает
первоначальный однотикерный прототип. Портфель требует ведущего процесса,
который координирует весь рынок.
